# Agent 任务拆分与交付流程

本约定自 2026-11-08 起生效。起因是桌面崩溃修复将复现、修改、不同桌面环境验证和截图集中在一个任务中，运行超过 40 分钟仍未交付，且截图使用已经不存在的窗口导致异常等待。任务存活不能代表任务正在有效推进。

## 1. 先记录，再派发

主 agent 在 `TASKS.md` 中登记任务，随后派给全新 pi 会话。任务正文必须自包含，至少包括：

| 字段 | 必填内容 |
|---|---|
| 目标 | 一个可独立验收的结果 |
| 写入范围 | 允许修改的文件或目录，以及明确禁止修改的范围 |
| 输入与依赖 | 现有源码、已确认接口、报告；前置结果是否已到位 |
| 验收 | 必须执行的检查、预期结果、报告或产物路径 |
| 预算 | 预计完成时间、检查点、每条外部命令超时 |
| 停止条件 | 何时交付、何时回报阻塞、哪些工作不得继续扩展 |
| 追踪 | Orca task/dispatch ID、状态、证据与后续任务 |

一般任务预计 10–20 分钟；预计更久时进一步拆分，或在派发前说明不可拆分的原因。耗时构建可以单列，不把等待编译与未知 GUI 问题混在一起。

## 2. 标准拆分

| 阶段 | 交付物 | 不包含 |
|---|---|---|
| 诊断 | 最小复现、关键日志、事实与假设、修复建议 | 产品修改、全功能回归 |
| 最小修复 | 限定文件中的修改、相关单测结果 | 多桌面环境验证、最终安装 |
| 定向验证 | 对约定故障的修复前后证据、失败和跳过项 | 追加不相关功能测试、反复截图 |
| 构建交付 | 最终二进制、摘要、启动/升级步骤、文档汇总 | 重复诊断、擅自安装或提交 |

需求简单且一次命令即可完成的工作由主 agent 直接处理，不为形式制造子任务。独立模块可并行；有依赖的阶段等所需证据或接口交付后再开始。未知原因诊断与最终验证不由同一长任务无限串行推进。

## 3. 检查点与阻塞处理

- worker 开始后先确认输入与边界；预计超过 20 分钟时，先回报已完成项、具体阻塞和最短剩余步骤，不静默延长任务。
- 主 agent 收到检查点或用户询问时检查状态及最近证据。Orca 自动唤醒时处理回报，不用轮询脚本占用消息收件箱。
- 截图默认最长 10 秒；普通探针最长 30 秒；GUI 场景最长 60 秒。构建、测试按实际需要显式设更长上限，并说明原因，不能无限等待。
- 同一命令连续两次失败且没有新证据时，停止重复，记录失败并请求协调。窗口失效时先重新确认目标，禁止继续拿旧窗口 ID 截图。
- 外部条件无法满足时保留任务未完成状态，列出缺失条件；将可独立进行的剩余工作拆为后续任务。
- 超时不会自动授权终止进程。只可按工具规则清理明确属于自己任务的测试资源；不得触碰用户程序和系统无障碍、代理等服务。

## 4. 停止与交付

worker 完成约定检查即报告，不追加全量测试、多环境试验或美化截图。报告包含：文件改动、实际命令及退出结果、测试通过/失败/跳过数量、产物路径和摘要、未验证项。

主 agent 核对证据和产物，仅补证据缺口；更新 `TASKS.md`、必要的 `VERIFICATION.md`，再向用户汇报。代码完成、定向验证完成、正式构建完成、用户真机验收必须分别描述。

## 5. 文档维护规则

- 派发、完成、阻塞、取消或重新拆分时更新 `TASKS.md`。
- 已派发任务不能只改文档就声称 Orca 状态也改变；两个状态分别如实记录。
- 规则变更写入本文件；影响所有 agent 的要求同步到根目录 `AGENTS.md`。
- 不覆盖历史验收证据；更正错误时标明旧结论和新依据。


## 6. 宿主桌面影响（2026-11-08 补充）

本项目测试遗留 portal 使用失效临时总线，RustDesk server 随后使用相同地址；详见 TASKS 的只读核查。暂停在宿主真实桌面执行新增 GUI 实验。临时 D-Bus 会自动激活 portal、无障碍服务等进程，结束主应用/总线不代表这些进程已退出。测试前记录已有进程、显示与会话边界；测试后核对所有自动激活资源，不得仅凭主脚本退出宣称清理完成。使用不同 D-Bus 却继承真实 XDG_RUNTIME_DIR、DISPLAY/Wayland 环境不构成完整隔离。无法保证独立测试会话时，报告未验证，不再扩大宿主实验。


2026-11-08 RD-01 已精确清理测试残留，RustDesk 子进程自动恢复正式总线；详见 TASKS。此后 GUI 验证仅限专用虚拟机或确认独立于宿主桌面的容器，不再以宿主临时 D-Bus/Xvfb 作为回退。任务派发必须写明这一禁止项，且执行前检查；缺乏隔离环境就报告未验证。
