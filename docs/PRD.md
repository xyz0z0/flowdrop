## 1. 项目概述

### 1.1 一句话定位

FlowDrop 是一个面向个人多设备的轻量化、私有部署的**跨设备共享收件箱**：在 Linux、Windows、Android 等设备之间方便地分享文字、链接、图片、APK 和普通文件，无需反复手动找文件、选择传输方案。

### 1.2 用户问题

- 主力电脑生成 APK，想在手机上立即下载并安装体验，但反复拷贝麻烦。
- 手机上截图、复制文字、看到链接，希望迅速交给电脑使用。
- 有时两台设备在同一 Wi-Fi，有时靠 Tailscale 互联；不想每次切换工具。
- 传统文件同步需要管理文件夹，点对点工具需要明确选择接收设备；用户更想“发送一次，自己的其他设备随时取用”。

### 1.3 产品原则

1. **共享收件箱优先**：默认将内容发送到个人收件箱，而不是强制选择目标设备。
2. **同一体验**：Wi-Fi、Tailscale 使用同一套 Web UI 和 HTTP API，不为网络环境引入两套业务逻辑。
3. **少操作**：发送、预览、复制和下载的路径尽可能短。
4. **本地优先与隐私**：内容保存在用户控制的 Hub，不默认上传第三方云。
5. **小步迭代**：先做 Web MVP，后续按真实使用需求添加 Android 原生分享入口和桌面客户端。

### 1.4 非目标（MVP 不做）

- 不做跨互联网匿名文件分享、公共用户注册或自建 NAT 穿透。
- 不做手机后台静默读取全部剪贴板；Android 系统对此有限制。
- 不做自动静默安装 APK（普通 Android 设备通常需用户授权和确认）。
- 不做完整文件夹双向同步、版本冲突解决、团队协作、聊天软件、端到端加密多用户协议。
- 不做必须依赖某一家云服务的系统。

## 2. 典型用户故事与验收标准

| ID | 场景 | 验收标准 |
|---|---|---|
| US-01 | Kubuntu 发文字到手机 | 电脑输入并发送文本，手机打开收件箱后可看到、复制；在线页面自动更新，无需刷新 |
| US-02 | 手机分享截图到电脑 | 手机 Web 上传 JPG/PNG，电脑能预览并下载原文件 |
| US-03 | 电脑发送 APK | 上传 APK 后，手机能看到文件名、大小，下载后由系统发起安装并进行必要的用户确认 |
| US-04 | 传普通文件 | 支持任意常规文件类型的上传、下载与进度反馈；文件内容保持一致 |
| US-05 | 网络变化 | 同 Wi-Fi 可用局域网服务地址；不在同 Wi-Fi 时用 Tailscale 地址仍可访问；V1 不强制自动切换地址 |
| US-06 | 数据保护 | 未认证客户端不能查看、上传、下载收件箱内容；文件下载不允许绕过权限 |
| US-07 | 断线重连 | 浏览器 WebSocket 断开后能重连并补拉最新内容，不丢失已成功提交的条目 |
| US-08 | 历史管理 | 可以删除本人收件箱条目；过期清理删除元数据和附件文件 |

## 3. MVP 功能范围

### P0（必须完成）

1. 单用户 Hub：提供 Web UI、REST API、WebSocket 新条目事件、文件存储、SQLite 元数据。
2. 内容类型：`text`、`link`、`image`、`file`；APK 作为 `file` 处理，可增加 APK 标签。
3. 发送：输入文字/URL；粘贴图片（在浏览器支持的情况下）；选择文件上传；拖拽上传。
4. 浏览：按时间倒序的收件箱；展示来源设备昵称（由客户端设置）、内容预览、文件信息。
5. 操作：复制文本/链接、打开链接、预览图片、下载附件、删除条目。
6. 安全：初始管理员凭据或一次性配对密钥；访问会话；鉴权覆盖所有 API、WS、下载；安全默认绑定地址。
7. 连接：允许通过局域网 IP 与 Tailscale IP 访问；不依赖局域网广播发现。
8. 稳定性：上传大小上限、流式写入、临时文件原子落盘、合理错误提示、断线重连、基础日志。

### P1（完成 MVP 后）

1. Android 原生轻客户端：注册系统 `ACTION_SEND`、`ACTION_SEND_MULTIPLE`，从系统分享菜单发送文本、图片和文件。
2. APK 自动发布：监听配置目录，待文件写入稳定后自动作为新条目发布；支持 CLI `flowdrop publish path/to/app.apk`。
3. 通知：在线页面提示新内容，Android 原生通知仅在具备权限和可靠后台策略时启用。
4. 内容过期策略：默认保留 7 天，可选 30 天、永不自动删除；容量上限与手动清理。
5. 设备管理：设备别名、吊销访问凭据、最近活动时间。

### P2（需求验证后）

- Tauri 桌面端、剪贴板的**手动**一键发送、全局快捷键。
- 可选局域网发现与智能 URL 选择；注意同 Wi-Fi 不代表必定可直连。
- 更完整的构建历史、项目标签、文件批量传输、搜索。
- 可选独立中继与更细粒度的安全模型（必须单独设计）。

## 4. 用户流程

### 4.1 首次使用

1. Kubuntu 安装并启动 Hub，初始化数据目录、管理员认证密钥。
2. Hub 显示本机可用访问 URL（局域网/Tailscale 由用户自行配置和验证）。
3. 手机打开该 URL，完成登录/配对；保存网页到桌面可作为便捷入口。
4. 登录成功显示同一份共享收件箱。

### 4.2 文本发送

1. 打开 FlowDrop → 输入或粘贴内容 → 点击发送。
2. 服务端创建条目并持久化 → WebSocket 广播事件。
3. 其他在线设备收件箱显示条目；点击一键复制。

### 4.3 文件发送

1. 选择/拖入文件 → 显示传输进度 → 上传完成后创建条目。
2. 接收设备可预览图片，或下载附件。
3. 下载 APK 后由 Android 系统引导确认安装；无需 FlowDrop 申请越权静默安装能力。

### 4.4 外网使用

用户开启两端 Tailscale，在手机通过主力电脑的 Tailscale IP/MagicDNS 名称及正确端口访问 Hub。**Tailscale 负责连通性，应用仍须认证。** 不使用未经保护的公网端口映射作为默认方案。

## 5. 推荐架构

```text
         Kubuntu / Windows 浏览器          Android 浏览器（MVP）
                  |                             |
                  +---------- HTTPS -----------+
                             |
               Wi-Fi LAN 或 Tailscale
                             |
                  +---------------------+
                  |    FlowDrop Hub     |
                  | Go HTTP Server      |
                  | REST + WebSocket    |
                  | Auth / Rate Limit   |
                  +----------+----------+
                             |
                   +---------+---------+
                   |                   |
                SQLite            Blob Storage
              metadata          (managed files)
```

### 5.1 技术栈

- 服务端：Go；HTTP Router（优先 Go 标准库或成熟轻量路由器）、WebSocket 库。
- 前端：TypeScript + React + Vite；移动优先响应式页面。
- 数据库：SQLite；文件不放数据库，存入数据目录 `blobs/`。
- 部署：Linux 二进制 + systemd 用户服务；前端静态资源可嵌入 Go 二进制。
- 通信：REST（操作）+ WebSocket（变更通知），掉线后 REST 补拉。
- 后续客户端：Android Kotlin/Jetpack Compose；桌面端如需要再评估 Tauri。

### 5.2 重要实现约束

- 不从浏览器直接读取用户系统剪贴板的后台内容；剪贴板操作必须遵守浏览器权限与用户手势限制。
- 跨 LAN/Tailscale 的浏览器安全上下文与证书要明确规划：优先使用经验证的 HTTPS 方案（如 Tailscale Serve），不要假定对任意 IP 的 HTTP 自动拥有全部浏览器能力。
- 持久化 WebSocket 只负责实时通知，不作为唯一消息存储；以 SQLite 为权威状态。
- 上传先写随机临时文件，校验大小/摘要并完整 flush 后再提交元数据；失败清理临时文件。
- 以随机 ID 组织存储路径，不使用客户端原始文件名拼接磁盘路径；下载时规范化响应头并防止路径遍历。
- MIME 类型、扩展名不可信；图片预览需限制格式，并设置适当 `Content-Type` 与 `Content-Disposition`。

## 6. 建议数据模型

### inbox_items

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT (UUID/ULID) | 条目 ID |
| type | TEXT | text/link/image/file |
| text_content | TEXT NULL | 文字或链接 |
| blob_id | TEXT NULL | 文件记录引用 |
| sender_device | TEXT | 来源设备 ID / 昵称 |
| created_at | INTEGER | UTC 时间戳 |
| expires_at | INTEGER NULL | 可选过期时间 |

### blobs

| 字段 | 类型 | 说明 |
|---|---|---|
| id | TEXT | 随机文件 ID |
| original_name | TEXT | 显示/下载名，不参与实际存储路径 |
| content_type | TEXT | 经服务端处理的 MIME |
| size_bytes | INTEGER | 文件长度 |
| sha256 | TEXT | 完整性摘要 |
| storage_key | TEXT | 内部随机存储键 |
| created_at | INTEGER | 时间 |

可增加 `devices` / `sessions` 表存储设备身份、会话哈希、吊销状态。

## 7. 初版 API 草案（可由实现者合理调整）

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/api/v1/auth/login` | 登录/配对，签发会话 |
| POST | `/api/v1/auth/logout` | 注销会话 |
| GET | `/api/v1/items?cursor=...&limit=...` | 分页获取收件箱 |
| POST | `/api/v1/items/text` | 创建文字/链接 |
| POST | `/api/v1/items/upload` | multipart 文件上传并创建条目 |
| GET | `/api/v1/items/{id}` | 查询条目 |
| DELETE | `/api/v1/items/{id}` | 删除条目和关联文件（按引用关系处理） |
| GET | `/api/v1/items/{id}/download` | 鉴权后下载附件 |
| GET | `/api/v1/events` | WebSocket；发送 `item.created` / `item.deleted` |
| GET | `/api/v1/health` | 健康检查；不泄露敏感内容 |

建议服务端生成 `id`、时间戳、下载路径，客户端不自行拼接或信任任意服务端文件路径。

## 8. 安全要求（不能后补）

1. **身份认证**：首次启动生成高熵初始化密钥，完成管理员初始化；认证凭据不要写入日志或源码。存储密码使用成熟的慢哈希；令牌只存哈希或采取等效安全措施。
2. **传输保护**：跨设备使用可信 HTTPS；建议首版通过 Tailscale Serve/受信任反向代理提供 TLS，并校验访问入口。切勿将无 TLS 的认证页面暴露在不可信网络。
3. **访问控制**：所有条目、附件和 WebSocket 必须鉴权；不能仅凭知道随机文件 ID 就下载。
4. **防恶意文件**：限制文件大小与可用空间；禁止路径遍历；设置安全下载头；避免直接 inline 渲染 HTML/SVG 等主动内容。
5. **隐私**：默认不采集系统剪贴板，不扫描无关文件夹；不接入外部分析 SDK；日志不记录内容原文。
6. **限流**：认证尝试、上传和 API 应设置基本限流与资源占用上限。
7. **数据清理**：过期删除、手动删除都应清理文件与元数据；提供明确的备份和恢复方式。
8. **安全边界**：Tailscale 的网络 ACL 不能取代应用层鉴权。

## 13. 关键产品决策与待验证假设

## 15. 实施澄清（v0.1 实现基线补充，2026-11-07）

> 本节由实现阶段补充，**不修改上文原始需求**；冲突时以上文为准，范围问题以本节澄清为准。原始文档保留在仓库根目录 `flowdrop-prd.md`。

### 15.1 登录方式
日常登录使用**管理员密码**（单用户）。首次初始化在 Hub 本机执行 `flowdrop admin init`（交互式输入，不回显；直接写数据库），不提供远程注册/远程初始化端点，也不把设备配对码作为日常登录方式。此实现比“一次性初始化密钥”更小暴露面，故以此替代第 8 节第 1 条中的初始化密钥路径。

### 15.2 网络与 HTTPS
- Hub 默认只监听 `127.0.0.1`，不默认暴露公网端口。
- Tailscale 路径使用 `tailscale serve`（HTTPS + MagicDNS），由 Tailscale 终结 TLS。
- 纯 Wi-Fi（手机不装 Tailscale）路径：局域网 HTTPS 入口。推荐 Caddy `tls internal`（本地 CA），手机必须导入并信任该 CA；文档给出可操作步骤。**不接受**“忽略证书警告 + 局域网明文 HTTP”作为完整方案。
- 应用不使用 `X-Forwarded-*` 做安全决策，除非来源 IP 命中显式配置的可信代理列表；允许的 Host / Origin 显式配置。

### 15.3 US-08 范围澄清（重要）
US-08 原文：“可以删除本人收件箱条目；过期清理删除元数据和附件文件”。
MVP 实现为：

1. **手动删除**条目并清理其附件（必须，已实现）。
2. **临时文件与孤立附件清理**（必须，已实现）：启动时与周期性回收未被数据库引用的附件、陈旧上传临时文件。
3. **自动过期**：MVP **不实现**。`expires_at` 字段保留在模型中但不参与自动删除；界面不展示过期时间。自动过期策略（默认 7 天等）按上文归入 **P1**，不在初版实现。

### 15.4 上传约束
- 单文件上限默认 512 MiB，可通过配置调整；多选文件由客户端**逐个上传**，每个附件一个条目；不做断点续传。
- 上传失败不产生可见条目；临时文件完成大小校验、SHA-256 与 `fsync` 后原子 `rename` 到存储目录，再提交元数据事务，提交成功后才广播。

### 15.5 通知与移动端
在线页面通过 WebSocket 实时更新；浏览器后台/移动端不保证常驻连接或系统通知。页面恢复前台或重连后通过 REST 重新拉取列表（含断线期间删除）。APK 下载后由 Android 系统执行安装授权，应用不申请静默安装。

## 16. 范围澄清追加（2026-11-07，第二轮：HTTP LAN + Android 原生）

> 本节为**追加记录**，不修改第 1–15 节的原文。与上文冲突时，以本节的最新产品决定为准；
> 第 15 节仍是“v0.1 实现基线”的历史记录。

### 16.1 用户已确认的产品形态

- **Linux Hub（Go 单进程）+ Android 原生 App + Web**。电脑端继续使用现有 Web 界面，
  不做 Linux 桌面壳、不做扫码配对、不做局域网自动发现。
- **网络主路径改为明文 HTTP 局域网**：Hub 直接监听**具体的局域网网卡 IP**
  （如 `192.168.1.10:8080`），手机与电脑在同一 Wi-Fi 下直接访问 `http://<Hub-IP>:8080`。
  **不需要** Tailscale、Caddy、也**不需要**导入任何证书。
- **跨网**（手机不在同一 Wi-Fi）仍使用用户**已有的 Tailscale**，不新增自建穿透。
- **认证不变**：保留单管理员密码登录；管理员初始化仍**只在 Hub 本机 CLI**
  （`flowdrop admin init`）执行，不新增任何远程初始化/配对/自创认证端点。
- **原生协议不变**：Android 客户端沿用现有 Cookie 会话 + CSRF 双提交 + Origin 校验，
  直接调用已有 `/api/v1/*`。**不新增自创认证端点**。

### 16.2 对第 15.2 节的修正

第 15.2 节写“不接受局域网明文 HTTP 作为完整方案”，该结论**已被用户明确推翻**，
现改为：

- 家庭可信 LAN 内使用**明文 HTTP** 是用户接受的主路径，属于**有意识的安全边界取舍**：
  传输不加密，同网段的其它设备/中间人理论上可读取内容与 Cookie。
- 应用侧因此必须做到：Cookie 的 `Secure` 关闭（`FLOWDROP_COOKIE_SECURE=false`）、
  监听地址显式绑定具体局域网 IP（`FLOWDROP_LISTEN`，禁止 `0.0.0.0`/`::`）、
  访问用的其它主机名（mDNS 名、Tailscale MagicDNS 名）显式列入
  `FLOWDROP_ALLOWED_HOSTS`（监听 IP 本身自动允许）。这三项均为现有配置项，
  **不新增配置键**。
- **原 HTTPS / Tailscale Serve / Caddy 部署保留为可选方案**，适用于不可信网络或需要
  加密传输时；文档不再把它写成必需前置条件。

### 16.3 浏览器能力的诚实边界（重要）

明文 HTTP 的局域网地址**不是浏览器的 secure context**。因此：

- **不承诺** LAN HTTP 下 `navigator.clipboard` 可用、不承诺后台剪贴板读写、
  不承诺 Service Worker / 通知等仅安全上下文可用的 API。
- Web 端所有复制入口（正文/链接、SHA-256 等）在自动复制失败时，必须
  **给出可手动选择的文本**，并说明失败原因；**不得**抛未捕获异常，
  **不得**谎报“已复制”。
- 该降级是产品行为的一部分，不是待修复的缺陷。

### 16.4 范围外（仍然不做）

- Linux 桌面壳、系统托盘、文件管理器集成。
- 手机扫码配对、mDNS/SSDP 自动发现、二维码引导。
- 自建公网穿透、动态 DNS、自动证书签发。
- 多用户、团队空间、端到端加密。

### 16.5 验收口径调整

第 12 节 Definition of Done 中“LAN 与 Tailscale 路径均经过手动实测”仍成立，但
**LAN 路径改为明文 HTTP 验收**（不再要求 CA 导入）；Android 端由原生 App 承担，
Web 端在手机浏览器上仍应可用。二者均需真实设备实测，未实测前不得声称通过。

### 16.6 配置约束（实现侧实测补充）

选写具体的局域网 IP 而非通配地址，不只是风格问题——Hub 在 `cookie_secure=false` 时
**拒绝** `0.0.0.0` / `::` / 空 host 启动（`listen must name the specific LAN IP when cookie_secure=false`），
以避免明文端口出现在每一张网卡上。文档据此写 `FLOWDROP_LISTEN=<Hub-IP>:8080`。
监听的具体 IP 会自动加入 Host 白名单；`FLOWDROP_ALLOWED_HOSTS` 只用于补充 mDNS 名、
主机名或 Tailscale MagicDNS 名等额外访问名。

## 17. 范围澄清追加（2026-11-07，第三轮：局域网自动发现 + Tailscale 绑定说明）

> 本节记录用户最新要求，**局部覆盖** §16.1/§16.2/§16.4 中“不做局域网自动发现”和
> “不新增配置键”的旧结论。HTTP + 密码登录仍是主路径；纯 Wi-Fi 可信家庭网络
> **仍然不需要** TLS、Caddy 或 Tailscale。
>
> **历史说明（2026-11-08）**：本节当时“不新增多监听、保留单 IP 限制”的结论已被
> §19 取代。以下第 17 节正文保留为当时版本的记录；其中发现协议与启用条件仍然有效。

### 17.1 新增需求

- 新增 **mDNS/DNS-SD 局域网自动发现**，让同一 Wi-Fi 的客户端无需手输 IP 即可找到 Hub。
- ~~保留**单 IP 监听**限制；LAN 与 Tailscale 直连仍需重启切换绑定地址。~~
  **已由 §19 取代（2026-11-08）**：同一 Hub 可同时监听 LAN + Tailscale。
- 补充**怎样绑定 Tailscale** 的部署说明（见 DEPLOY §7.1）；本轮不改变网络架构。
- 发现是**可选增强**：发布失败只记录日志，不得使 Hub 的基本收发失败。

### 17.2 冻结的发现协议（Hub 与 Android 必须一致）

| 项 | 值 |
|---|---|
| 协议 | mDNS / DNS-SD（RFC 6762 / 6763） |
| 服务类型 | `_flowdrop._tcp` |
| 域 | `local.` |
| 实例名 | `FlowDrop-<主机昵称>`；昵称安全截断到 63 字节 DNS label，冲突时加 `-2`、`-3`… |
| SRV | port = 真实 Hub 监听端口 |
| 地址（A） | **仅**绑定的具体 RFC1918 LAN IPv4，且只从对应网卡发布 |
| TXT | `v=1`、`scheme=http`、`path=/` |

不包含密码、会话令牌、条目正文或机器路径。客户端用 `scheme=http` + A 地址 + SRV 端口
+ `path=/` 构造入口 URL。Android 按同一协议实现；协议变更必须先与协调者确认。

### 17.3 启用条件与开关

- **默认行为**：当 `listen` 是具体 RFC1918 IPv4（10/8、172.16/12、192.168/16）、
  `cookie_secure=false`，且该地址在 Up + Multicast 的本机网卡上时，自动发布。
- **显式关闭**：`discovery_enabled=false` 或 `FLOWDROP_DISCOVERY_ENABLED=false`。
  这是本轮唯一新增配置键；`true` 表示明确希望启用，但地址不合格时仍然跳过并记日志。
- **不发布**：回环、通配（`0.0.0.0`/`::`/空 host）、Tailscale `100.64/10`、
  链路本地、公网 IPv4、IPv6、以及 `cookie_secure=true` 的 HTTPS/TLS 反代入口。
  HTTPS 反代入口不得冒充可直接连接的 LAN HTTP 入口。
- 不在所有网卡广播；只向绑定的那块网卡发送，A 记录只有该绑定 IPv4。
- 与系统 Avahi 共用 UDP 5353 为**尽力而為**；被占用时记日志告警，不令 Hub 失败。
  不依赖必须安装 Avahi/Caddy/Tailscale。正常退出发送 TTL=0 注销并释放 socket。

### 17.4 验收口径（不得混淆）

- `go vet` / `go test`（含发现配置、地址范围、网卡绑定范围、生命周期）通过；
  现有 API 回归保持。
- 使用**独立 mDNS 浏览器或可复现协议探针**实际发现本机发布，核对 SRV/TXT/A/IP/端口；
  验证关闭时不发布、Tailscale 绑定跳过广播。模拟测试与实际探针必须分开记录。
- **普通 HTTP 健康检查不能当作发现成功**；未做真实手机/跨网验证时必须明确说明。
- 详细实际结果见 `docs/VERIFICATION.md §12`。

## 19. 范围澄清追加（2026-11-08，第四轮：内网 + Tailscale 同时使用）

### 19.1 用户要求与产品结论

用户明确要求桌面 Hub **同时支持内网（LAN）与 Tailscale**，不再要求每次切换绑定地址。
本轮只解除旧版“单 IP 产品限制”，不扩展其它功能：

- 默认仍是单地址（旧方式）；用户可显式选择「同时使用内网和 Tailscale」。
- 双模式选择**两个本机具体 IPv4**：一个 RFC1918 LAN 地址 + 一个 Tailscale 地址，
  使用**同一端口**。LAN 是主地址（`listen`），Tailscale 是附加地址（`additional_listen`）。
- 仍**不监听** `0.0.0.0` / `::`；不启动两个 Hub；不让两个进程共享数据目录；
  不自动选路、不自动网络重绑定、不自动安装/配置 Tailscale。
- 没有 Tailscale 网卡时：双模式明确不可选，内网单模式仍可用；提示不要求安装 Tailscale。

### 19.2 冻结接口（Hub 与桌面）

- `hub.Options.AdditionalListen []string`：`nil` 继承配置；非 nil（含空 slice）显式覆盖。
- `Hub.URLs() []string`：全部实际监听 URL，主地址在前；`Hub.URL()` 保持主地址。
- `config.additional_listen` + `FLOWDROP_ADDITIONAL_LISTEN`。
- 所有监听共享**同一** Hub/HTTP handler/数据库/认证会话/Broker/数据目录锁；
  全部绑定成功才启动，否则回滚并释放已绑定端口；`Stop` 释放全部。
- mDNS 只向符合条件的 RFC1918 LAN 接口发布；Tailscale 监听不冒充 LAN 入口。
- CLI 与 Android 的 HTTP 协议不变；Android 填任一可达地址即可。

### 19.3 桌面设置要求

- 设置窗口清晰呈现两种方式：单地址（保留旧设置与 `desktop.json` 兼容）与
  「同时使用内网和 Tailscale」。
- 双模式分别选择 LAN / Tailscale 具体 IPv4，显示将使用的端口与说明；
  只列出本机真实网卡地址，不伪造地址。
- 运行状态只显示 `Hub.URLs()` 的**实际绑定 URL** 与类型；未运行/未绑定的配置地址
  只作为输入，不显示成可用。收件箱优先 LAN 地址（系统代理提示保留）。
- 保存并重启：当前绑定地址失效、端口占用或任一监听失败时，明确错误并尝试恢复原配置；
  不静默半启动；失败的选择不写入配置。
- 跨 host 的 Cookie 沿用浏览器规则，不承诺自动共享登录态；不新增 LAN 管理端点。

### 19.4 验收口径

- Go 测试覆盖：旧 `desktop.json` 兼容、双地址校验、真实 Hub 双监听共享数据/会话/WS、
  启动原子失败、单模式不继承 config 中的 additional、失败回滚。
- 真实桌面 App 实测：保存/重启双模式；两个地址的健康检查、登录、WS、收发；

- 文档保留旧单 IP 限制为历史版本说明，不覆盖既有验证证据；给出 CLI
  `FLOWDROP_LISTEN` + `FLOWDROP_ADDITIONAL_LISTEN` 示例与桌面操作说明。
